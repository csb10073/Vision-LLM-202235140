# 의료 약물 투약 절차 검증 에이전트 (Jetson 온디바이스)

카메라로 사용자가 **파란색 물체 → 빨간색 물체** 순서로 시연하는지 확인하고, 시연하는 동안 녹음한 설명에서 사용자가 **말로 설명한 순서**도 함께 비교해 결과를 한국어 음성으로 알려주는 프로그램입니다.
YOLO 탐지, Whisper 음성 인식, Piper 음성 합성, Gemma 보고서 생성까지 모두 NVIDIA Jetson 위에서 온디바이스로 동작하도록 작성되었습니다.

## 주제 선정 배경과 활용 가능성

**이 주제를 선택한 출발점은 의료 분야에서 약물을 잘못된 순서로 투여하는 등의 절차 오류를 줄이고 싶다는 문제의식입니다.** 사용자가 순서를 말로 설명한 내용과 실제 행동을 함께 확인하면, 설명과 수행 중 어느 부분에서 오류가 생겼는지 구분하는 데 도움을 줄 수 있다고 보았습니다. WHO도 약물 사용 과정의 오류가 심각한 위해로 이어질 수 있어 예방이 중요하다고 설명합니다. 

현재 프로젝트에서는 이러한 문제를 **파란색 물체 → 빨간색 물체라는 간단한 과제로 줄여 구현**했습니다. 실제 약물의 종류나 처방을 판단하는 기능은 없으며, 두 물체를 구분하고 수행 순서와 설명 순서를 비교하는 기본 구조를 확인하는 시제품입니다. 투약 사고 예방 효과는 아직 검증하지 않았습니다.

### 여러 분야에 맞게 바꿔 쓸 수 있는 이유

공통으로 필요한 기능은 ‘대상 구분 → 행동 순서 기록 → 설명과 비교 → 결과 보고’입니다. 이 구조를 바탕으로 검사할 대상, 기준 순서, 보고서 목적을 바꾸면 다른 분야에도 적용할 가능성이 있습니다. 여기서 분야는 의료·노인 활동·작업 교육처럼 실제로 사용하는 상황을 뜻합니다.

| 활용 분야 | 바꿔 적용할 수 있는 과제 | 보고서에서 다룰 내용 |
|---|---|---|
| 의료 절차 교육 | 모형 약물이나 도구를 정해진 순서로 제시하는 훈련 | 기준 절차와 실제 수행·설명의 일치 여부 |
| 노인 대상 인지 활동 | 색이 다른 물체 분류, 제시된 색 순서 기억과 재현 | 색 분류와 순서 재현에서 관찰된 성공·오류 |
| 작업·생활 절차 교육 | 준비물 제시나 작업 단계의 순서 확인 | 빠진 단계, 순서 오류, 설명과 행동의 차이 |

이 표는 **향후 활용 방향**입니다. 현재 코드는 파랑·빨강 두 색과 두 단계에 맞춰져 있어, 분야 확장에는 대상 인식 방식과 판정 규칙도 함께 바뀌어야 합니다.

### 색으로 물체를 분류한 이유

색은 물체의 복잡한 이름이나 긴 글을 읽지 않고도 눈으로 구분할 수 있는 단서입니다. 특히 노인 대상 활동에서 색을 보고 물체를 나누거나 순서를 기억하도록 구성하면, 과제를 직관적으로 이해하고 참여하는 데 도움이 될 것이라고 기대했습니다. **색 구분과 순서 기억을 연습하는 인지 활동으로 확장하는 것**이 목표입니다.

다만 ‘색을 썼기 때문에 모든 노인이 쉽게 인지한다’거나 ‘인지능력이 향상된다’는 효과를 확인한 것은 아닙니다. 나이가 들면서 일부 색을 구별하기 어려워질 수도 있다는 점은 자료를 찾아보면 나옵니다. 따라서 향후에는 사용자의 시각 특성을 고려해 색과 함께 모양·큰 글자·음성 안내를 제공하는 설계와 실제 사용자 평가가 필요합니다.

## 동작 흐름

시연 1회(Enter 한 번)는 다음 순서로 진행됩니다.

1. CSI 카메라를 열고 **15초 동안 카메라 처리와 마이크 녹음을 동시에** 진행합니다.
2. 각 프레임의 가운데 영역(상하좌우 10% 제외)에서 YOLO로 병·컵(COCO 클래스 39, 41)을 찾고, 박스 안의 HSV 색으로 파랑/빨강을 판별합니다. `--color-only`이면 YOLO 없이 가운데 영역 전체의 색만 봅니다.
3. 처음에 빈 화면이 2프레임 연속 보이면 "준비 완료", 이후 같은 색이 2프레임 연속 보이면 한 단계로 확정합니다. 단계를 확정한 뒤 1.5초 동안은 새 관찰을 무시합니다.
4. 15초가 끝나면 녹음 파일을 Whisper(한국어)로 텍스트로 바꾸고, 정규식으로 "먼저 파란색, 그다음 빨간색" 같은 문장에서 순서를 추출합니다.
5. **화면 판정이 1차 기준**이며, 화면이 맞았을 때 음성 순서를 최종 판정에 반영합니다. 음성 순서 추출과 화면·음성 불일치 확인은 화면의 통과 여부와 관계없이 수행합니다.
6. Piper TTS로 "통과" 또는 "순서를 다시 확인하시오"를 스피커로 재생합니다. 화면과 음성의 순서가 다르면 "음성과 화면의 순서가 다릅니다."를 추가로 재생합니다.
7. 시연 기록을 `reports/trial_YYYYMMDD_HHMMSS.json`으로 저장합니다. Gemma를 사용하면 평가자용 요약 보고서(3문장 이내)를 기록에 함께 넣습니다. 이 보고서는 사용자에게 읽어주지 않습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `agent.py` | 실행 진입점. 인자 파싱, 필요한 모델 파일 확인, 모델 로드, 시연 반복 루프, 판정 후 음성 안내와 기록 저장 |
| `devices.py` | 하드웨어·외부 프로그램 연결: CSI 카메라(GStreamer), `arecord` 녹음, `whisper-cli` 음성 인식, Piper TTS와 `aplay` 재생, 미리보기 창 |
| `vision.py` | YOLO(Ultralytics, TensorRT 엔진) 탐지, HSV 기반 파랑/빨강 판별, CLAHE 밝기 보정, 중앙 ROI 자르기 |
| `procedure.py` | 프레임별 색 관찰을 단계로 확정하는 상태 머신, 화면 판정, Whisper 문장에서 말한 순서 추출, 최종 판정 |
| `report.py` | 시연 기록 JSON 저장, 기록을 문장으로 바꿔 Gemma(llama-cpp-python)로 평가자용 보고서 생성 |

## 순서를 판단하는 원리

**확인하려는 것은 실제로 보여준 순서와 말로 설명한 순서가 모두 기준인 파랑-> 빨강에 맞는지입니다.** 화면에서는 색이 단계로 확정된 시간순으로 기록하고, 음성에서는 색 이름 주변의 순서 표현을 찾아 비교합니다. Gemma는 판정이 끝난 기록을 평가자용 설명으로 바꿉니다.

아래 내용은 현재 코드에 구현된 규칙입니다. 실제 Jetson에서 녹음부터 음성 판정까지 정상 동작했는지는 아직 확인되지 않았습니다.

### 1. 화면의 순서는 어떻게 판단방법

화면의 왼쪽·오른쪽 위치가 아니라 **시간이 지나며 어떤 색이 먼저 단계로 확정됐는지**를 봅니다. 담당 코드는 [vision.py](vision.py)의 `colors_in_crop()`, [devices.py](devices.py)의 `observe()`, [procedure.py](procedure.py)의 `Procedure.update()`와 `Procedure.result()`입니다.

1. **볼 영역을 좁힙니다.** 화면의 상하좌우 가장자리 10%를 제외한 가운데만 봅니다. 이를 ROI라고 하며, 사진에서 관심 있는 부분만 잘라 보는 것과 같습니다.
2. **물체와 색을 찾습니다.** YOLO로 병·컵을 찾고, 물체를 둘러싼 박스 안에서 파랑·빨강을 찾습니다. 색 판별에는 색상·선명함·밝기를 나눠 보는 HSV를 사용합니다. 작은 색 점을 무시하기 위해 색 덩어리 하나의 면적이 박스 면적의 12% 이상이면서 최소 25픽셀 면적 이상이어야 합니다. 픽셀은 사진을 이루는 작은 색 칸입니다. `--color-only`에서는 물체 탐지 없이 가운데 영역을 보며, 면적 기준은 2.5%이고 최소값은 같습니다.
3. **시작 기준을 잡습니다.** 파랑·빨강이 감지되지 않는 화면이 2프레임 연속 나와야 준비 완료가 됩니다. 프레임은 동영상을 이루는 사진 한 장입니다. 여기서 ‘빈 화면’은 모든 물체가 없다는 뜻이 아니라, 검사 대상 색이 감지되지 않았다는 뜻입니다.
4. **잠깐의 인식 오류를 걸러냅니다.** 준비 완료 뒤 같은 관찰이 2프레임 연속 나와야 한 단계로 확정합니다. 파랑만 보이면 `blue`, 빨강만 보이면 `red`, 두 색이 함께 보이면 `both`입니다. 2프레임은 처리한 사진 수 기준이므로, 일정한 초 단위를 뜻하지 않습니다.
5. **확정된 단계만 기록합니다.** 색과 시연 시작 후 경과 시간을 `events`에 추가하고, 물체 탐지 근거도 함께 남깁니다. 직전 단계와 같은 색은 계속 보여도 새 단계로 세지 않습니다. 단계 사이에 반드시 빈 화면이 있어야 하는 규칙은 없습니다.
6. **물체를 바꾸는 시간을 둡니다.** 단계 확정 후 1.5초 동안은 새 관찰을 무시합니다. 교체 중의 흔들림을 줄이지만, 이 시간 안에 지나간 색은 단계로 기록되지 않을 수 있습니다.

예를 들어 파랑을 3.42초에, 빨강을 7.81초에 확정했다면 화면 순서는 다음과 같습니다. 이 시간은 물체가 처음 등장한 정확한 순간이 아니라, 연속 관찰 조건을 만족해 단계를 확정한 순간입니다.

```text
events = [파랑 3.42초, 빨강 7.81초]
화면 순서 = 파랑 -> 빨강
기준 순서 = 파랑 -> 빨강
화면 판정 = pass
```

준비 완료 후 기록이 정확히 `blue → red`일 때만 화면이 통과합니다. 두 색이 함께 확정되면 `both_visible`, 빨강이 먼저면 `wrong_order`, 파랑만 있으면 `missing_red`, 파랑 → 빨강 → 파랑처럼 단계가 더 생기면 `extra_step`입니다. 색으로 단계를 구분하므로 같은 색의 서로 다른 물체를 구별하는 기능은 없습니다.

### 2. 음성의 순서는 어떻게 판단방법

**소리를 글자로 바꾸는 일과, 글에서 순서를 알아내는 일은 별도입니다.** [devices.py](devices.py)의 `transcribe()`가 Whisper로 한국어 문장을 만들고, [procedure.py](procedure.py)의 `spoken_order()`가 정해진 규칙으로 그 문장을 읽습니다.

```text
15초 동안 녹음 → Whisper → 한국어 문장 → 색 이름·순서 단서 찾기 → 음성 순서
```

먼저 문장에서 색 이름이 **정확히 두 번 나오고, 파랑 계열 한 번·빨강 계열 한 번**인지 확인합니다. 인식하는 표현은 다음과 같으며, 색 이름 안의 일부 띄어쓰기도 허용합니다.

| 색 | 코드가 찾는 표현 |
|---|---|
| 파랑 | 파란색, 파랑, 파랑색, 파란, 푸른색 |
| 빨강 | 빨간색, 빨강, 빨강색, 빨간, 붉은색 |

그다음 두 색 주변에서 ‘먼저’, ‘다음’, ‘전’ 등의 단서를 찾습니다. 단순히 문장에 먼저 등장한 색을 첫 단계로 삼지는 않습니다. 예를 들어 “빨간색 전에 파란색”은 빨강이라는 말을 먼저 했지만, 설명한 작업 순서는 파랑 → 빨강입니다.

Whisper 호출에는 `--no-timestamps`가 사용되며, 순서 판정에는 변환된 문장만 사용합니다. **각 색을 말한 시각과 화면에서 물체를 보여준 시각을 맞춰 비교하는 기능은 없습니다.** 화면과 녹음을 동시에 수집해도, 비교하는 대상은 각각에서 얻은 전체 순서입니다.

### 3. 문장에서 순서 단서는 어떻게 찾나요?

정규식은 ‘정해 둔 글자 모양을 찾는 검색 규칙’입니다. `spoken_order()`는 정규식으로 두 색을 찾은 뒤 문장을 **첫 색 앞 / 두 색 사이 / 둘째 색 뒤**로 나눕니다. 같은 ‘먼저’도 붙는 위치에 따라 가리키는 색이 달라지므로, 단어와 위치를 함께 확인합니다.

| 단서와 위치 | 문장 예시 | 추출하는 순서 |
|---|---|---|
| 첫 색 앞의 ‘먼저·처음·첫 번째·1번’ | 먼저 파란색, 빨간색 | 파랑 → 빨강 |
| 첫 색 앞의 ‘나중·두 번째·그다음·2번’ | 나중에 빨간색, 파란색 | 파랑 → 빨강 |
| 두 색 사이의 ‘다음·뒤·후·이후·부터’ | 파란색 다음에 빨간색 | 파랑 → 빨강 |
| 첫 색 바로 뒤의 ‘전·이전·앞’ 관계 | 빨간색 전에 파란색 | 파랑 → 빨강 |
| 둘째 색 뒤의 ‘먼저’ | 빨간색, 파란색 먼저 | 파랑 → 빨강 |
| 두 색 사이의 조사와 둘째 색 뒤의 관계 표현 | 빨간색은 파란색 다음 | 파랑 → 빨강 |
| 두 색 사이의 조사와 둘째 색 뒤의 관계 표현 | 파란색은 빨간색 전 | 파랑 → 빨강 |
| 두 색에 붙은 앞·뒤 순서 표현 | 파란색 먼저 하고 빨간색 나중 | 파랑 → 빨강 |
| 두 색 사이의 일부 동작 연결 표현 | 파란색을 보여주고 빨간색을 보여줍니다 | 파랑 → 빨강 |

동작 연결 표현에는 ‘보여주고’, ‘투여하고’, ‘투약하고’, ‘넣고’와 ‘보여준 다음’ 같은 일부 형태가 등록되어 있습니다. 모든 동사와 문장 구조를 이해하는 방식은 아닙니다.

찾은 단서는 `directions`라는 집합에 모읍니다. 집합은 같은 값이 여러 번 나와도 하나로 담는 상자입니다. 색을 말한 순서대로라는 단서는 `1`, 반대로라는 단서는 `-1`로 담습니다. 모인 값이 `1` 하나면 말한 색 순서 그대로, `-1` 하나면 반대로 돌려 반환합니다. 단서가 없거나 두 방향이 모두 모이면 `None`, 즉 확정 불가입니다.

### 4. 헷갈리게 말하거나 잘못 인식한 음성 처리법

**애매한 발화를 임의로 고쳐 정답을 만드는 대신, 현재 규칙으로 순서를 확정할 수 없으면 판단을 보류합니다.** 다음은 `spoken_order()`가 `None`을 반환하는 예시입니다.

| 상황 | 문장 예시 | 확정하지 않는 이유 |
|---|---|---|
| 순서 표현 없이 색만 나열 | 파란색, 빨간색 | 어느 색이 먼저라는 단서가 없음 |
| 색이 부족하거나 반복됨 | 파란색 다음 빨간색, 다시 파란색 | 서로 다른 두 색이 한 번씩 나온 조건을 만족하지 않음 |
| 말을 고침 | 파란색, 아니 빨간색 먼저 | ‘아니’ 같은 정정 표현이 포함됨 |
| 부정함 | 파란색 말고 빨간색 | ‘말고’ 같은 부정 표현이 포함됨 |
| 동시에 한다고 설명함 | 파란색과 빨간색을 동시에 보여줍니다 | 앞뒤 순서를 확정할 수 없는 표현이 포함됨 |
| 단서가 서로 충돌함 | 먼저 파란색 전에 빨간색 | ‘먼저 파란색’과 ‘파란색 전에 빨간색’이 반대 방향을 가리킴 |
| 인식 결과가 비어 있음 | 빈 문자열 | 비교할 색과 순서 단서가 없음 |

`UNCERTAIN` 규칙은 문장 전체에서 ‘아니·아닙·아닌·아닐·아냐’, ‘말고’, ‘않’, 일부 ‘못’ 표현, ‘동시·같이·함께’를 찾습니다. 발견하면 나머지 단서를 해석하기 전에 확정 불가로 처리합니다. 따라서 정정 뒤의 최종 의도를 골라내거나, 두 색을 함께 보여준 상황을 앞뒤 순서로 바꾸는 기능은 없습니다.

이 방식에는 한계도 있습니다. 순서와 무관하게 쓴 ‘같이’가 있어도 문장 전체가 제외될 수 있고, 등록되지 않은 문장 구조는 사람이 이해해도 확정되지 않거나 잘못 해석될 수 있습니다. Whisper가 색 이름이나 부정어를 잘못 받아쓰면 그 오류가 판정에 이어질 수 있습니다. 억양·말의 쉼·인식 신뢰도 점수로 뜻을 보정하는 처리는 구현되어 있지 않습니다.

### 최종 결과

| 화면 결과 | 음성 결과 | 최종 결과 |
|---|---|---|
| 화면 규칙에서 실패 | 어떤 결과든 | 화면의 실패 코드 유지 |
| 파랑 → 빨강으로 통과 | 확정 불가 | `speech_unknown` |
| 파랑 → 빨강으로 통과 | 빨강 → 파랑 | `speech_mismatch` |
| 파랑 → 빨강으로 통과 | 파랑 → 빨강 | `pass` |

즉, **음성 순서를 모른다는 것과 반대 순서로 말했다는 것은 구분합니다.** 화면이 실패해도 비교 조건이 갖춰지면 음성·화면 불일치 안내는 별도로 나올 수 있지만, 음성 결과가 화면 실패 코드를 덮어쓰지는 않습니다.

### 5. Local LLM Gemma의 역할


Gemma의 역할은 **이미 계산된 판정과 근거를 평가자가 읽기 쉬운 한국어 보고서로 정리하는 것**입니다. `agent.py`의 `play_feedback()`에서 처리하는 흐름은 다음과 같습니다.

```text
화면 단계 + Whisper 문장
          ↓
규칙으로 음성 순서 추출·최종 판정 → Piper로 고정 안내 문구 재생
          ↓
make_record(): 기준 순서·화면 단계·문장·음성 순서·판정 정리
          ↓
record_to_text(): 기록을 한국어 설명으로 변환
          ↓
Gemma: 평가자용 보고서 생성 → 터미널 출력·JSON 기록에 포함
```

Gemma에는 원본 영상이나 녹음 파일 대신 변환된 기록 문장을 전달합니다. 보고서 작성 지침은 다음 세 가지입니다.

- 실제로 보여준 순서와 말로 설명한 순서를 나누어 설명합니다.
- 기록에 없는 내용은 추측하지 않고, 기록된 판정을 따릅니다.
- 한국어 세 문장 이내로 작성합니다. 코드의 생성 길이 상한은 `MAX_TOKENS = 150`이며, 이는 문장을 만들 때 사용하는 작은 글자 조각의 수를 제한하는 값입니다.

이 지침은 모델에 주는 요청이며, 생성된 보고서가 항상 이를 지키는지 별도로 검사하는 코드는 없습니다. 다만 보고서 내용으로 기존 판정을 다시 바꾸는 경로도 없습니다. 사용자가 스피커로 듣는 것은 규칙으로 정한 ‘통과’ 또는 ‘순서를 다시 확인하시오’와 필요한 불일치 안내입니다.

`--no-gemma`로 실행하면 보고서 생성만 생략하고 화면·음성 순서 판정과 기록 저장은 유지합니다. 이 구조는 같은 인식 결과에 같은 판정을 내리기 쉽다는 장점이 있고, 다양한 말투를 이해하는 범위는 등록된 규칙에 묶인다는 한계가 있습니다.

## 덜 개발된 부분과 개선 방향

**현재는 두 색의 순서를 확인하는 기본 구조가 구현되어 있고, 사용자의 이해 정도를 근거 있게 설명하는 보고서와 분야별 적용 기능은 더 개발해야 합니다.** Gemma 보고서 생성 함수는 있지만, 보고서가 적절한지 자동 검사하거나 분야별로 역할을 바꾸는 기능은 없습니다.

| 항목 | 현재 구현과 한계 | 추가 개발 방향 |
|---|---|---|
| 음성 처리 전체 흐름 | 마이크 녹음 문제로 실제 장비에서 녹음 → 인식 → 순서 판정의 정상 동작을 확인하지 못함 | 녹음 문제 해결 후 실제 발화와 인식 결과를 비교하고, 애매한 발화의 처리도 검증 |
| 이해 정도에 대한 보고서 | Gemma가 설명 순서·화면 순서·최종 판정을 요약함. 한 번의 일치만으로 실제 이해나 인지능력 향상을 확인할 수는 없음 | 여러 번의 과제 기록과 오류 양상을 근거로 설명하고, 근거가 부족하면 판단 불가로 보고 |
| 분야별 설정 | 기준 순서는 `EXPECTED`, 인식 색은 `HSV_BOUNDS`, 보고서 지침은 하나의 `PROMPT`에 고정됨 | 대상·색·단계 수·기준 순서·모델 역할·보고서 형식을 분야별 설정으로 관리 |
| 보고서의 정답 노출 | Gemma 입력에 기준 순서와 판정 사유가 포함되고, 정답을 보고서에 쓰지 못하게 하는 별도 제한은 없음 | 평가자용·학습자용 입력과 출력을 구분하고, 학습자용 보고서에는 정답을 드러내는 정보를 제한 |
| 보고서 검증 | 기록 외 추측 금지와 세 문장 이내 등의 지침만 전달하며, 생성 결과를 자동 검사하지 않음 | 기록과의 일치 여부, 정답 노출, 출력 형식을 검사하고 부적절한 보고서는 고정 문구로 대체 |

### Gemma의 역할을 분야에 맞게 정하기

Gemma에는 ‘사용자가 순서를 잘 알고 있는지 설명하는 평가자 보조’ 역할을 줄 수 있습니다. 다만 현재 입력으로 확인할 수 있는 것은 **사용자가 말한 순서와 실제로 보여준 순서의 일치 여부**입니다. 정답을 따라 말한 것인지, 원리를 이해한 것인지까지 구별하는 기능은 아직 없습니다.

분야별 역할은 의료 절차 교육에서는 ‘훈련 기록 요약’, 노인 대상 활동에서는 ‘색 분류와 순서 재현의 관찰 기록’, 작업 교육에서는 ‘단계 누락과 순서 오류 설명’처럼 정할 수 있습니다. 각 역할에 맞춰 무엇을 관찰하고 어디까지 판단할지를 프롬프트에 명시하는 방식입니다. 프롬프트는 모델에게 맡길 일과 지켜야 할 범위를 적은 지침입니다.

### 보고서에 정답을 써 버리는 문제 줄이기

현재 `report.py`의 `record_to_text()`는 ‘기준 순서’, ‘판정 사유’, ‘화면의 각 단계’, ‘사용자 발화’를 Gemma에 전달합니다. 따라서 보고서에 올바른 순서가 그대로 나올 수 있습니다. 현재 보고서는 평가자용으로 터미널과 JSON에 남고 스피커로 읽히지는 않지만, 향후 학습자에게 보고서를 보여주는 기능에는 정답 노출을 제한하는 처리가 필요합니다.

모델의 역할과 금지 사항을 프롬프트에 적으면 출력 범위를 제한하는 데 도움이 될 수 있습니다. **프롬프트만으로 정답 노출을 완전히 막는다고 보장할 수는 없으므로, 입력을 줄이고 출력도 검사하는 처리가 함께 필요합니다.**

## 실행 방법

```bash
cd Project02
python3 agent.py --preview
```

1. 모델을 불러온 뒤 `Enter로 시연 시작, q로 종료 >` 프롬프트가 나옵니다.
2. Enter를 누르면 `녹음 시작...`이 출력됩니다. 카메라 가운데를 비워 두면 `준비 완료`가 출력됩니다.
3. 파란색 물체(병/컵) → 빨간색 물체 순서로 카메라 가운데에 하나씩 보여주면서 순서를 말로 설명합니다. **시연과 녹음은 Enter를 누른 뒤 15초 동안만** 진행됩니다.
4. 15초가 지나면 음성 인식 → 판정 → 스피커 안내 → 기록 저장이 진행됩니다. 다시 Enter를 누르면 다음 시연, `q`를 입력하면 종료합니다.

미리보기 창에서 `q`를 누르거나 Ctrl+C를 누르면 프로그램 전체가 종료됩니다.

- Jetson에서 실행하면 **카메라 쪽(물체·색 인식, `[인식 완료]` 단계 확정)은 동작**합니다.
- 하지만 **마이크 녹음이 제대로 되지 않는 것으로 보입니다.** 녹음이 비어 있으면 Whisper 결과도 비게 되어(`[사용자 음성] (인식된 문장 없음)`), 화면 순서가 맞더라도 최종 판정이 `speech_unknown`으로 끝나 음성 기반 검증이 정상적으로 이뤄지지 않습니다.
- 원인은 아직 확정하지 못했습니다.

- 향후 local 노트북에서 실행 가능하게 바꿀 예정
